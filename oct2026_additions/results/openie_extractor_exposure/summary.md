# OpenIE extractor-exposure check (Llama-3.1-8B OpenIE KGs)

Generated by `eval/_openie_extractor_exposure.py` (deterministic, lexical, no model calls; output sha256 `defc501a85974ae2`). Question: does the gold-free OpenIE KG contain gold evidence triples whose endpoints are not in the passage the extractor was given, i.e. candidate "recalled, not extracted" triples?

## Method

- Provenance. `baselines/build_openie_kg.py` makes one Llama-3.1-8B call per passage on `text[:3500]` (no title, no gold). Every relation edge stores `source_docs`, the passages whose call emitted that exact (s, relation, o). Synonym edges are ignored.
- Normalization: NFKD, accents stripped, lowercase, every non-word run to one space. Exact occurrence = word-boundary containment of the normalized endpoint in the normalized source passage; loose occurrence = token recall >= 0.8.
- Match modes (direction ignored unless `_dir`): `so` = identical normalized endpoints (primary); `sro` = `so` plus a shared relation content-token stem (5-char prefix); `so_alias` = 2Wiki endpoints may be any Wikidata alias; `so_fuzzy` = one endpoint's content-token set contains the other's, aliases included (loose; admits spurious pairs).
- A matched edge is a candidate "recalled" edge when its own object string does not occur in any of its source passages. A matched gold triple is a candidate when every edge that matches it is such an edge.
- Baseline: all OpenIE relation edges that match no gold triple under any mode (fuzzy included).
- Gold: 2Wiki = Wikidata `evidences` (dev.json) of the split questions; MetaQA = KB path triples from kb.txt (identical to kg_silver forward edges: sub200 True, holdout200 True); GraphRAG-Bench medical = kg_silver edges, which are the same Llama-3.1-8B OpenIE run over the released `evidence_relations` strings (the benchmark ships no triples). The two GraphRAG-Bench splits share one corpus and one OpenIE KG.

## Reading

The OpenIE KG is built by Llama-3.1-8B, which has seen Wikipedia in pretraining. Each extraction call saw one passage and nothing else, and every edge records its source passage, so a fact supplied from memory would surface as an edge whose endpoint is missing from that passage. On 2WikiMultiHop (both swap splits), 211 of 783 gold evidence triples (26.9%) are reproduced by 233 OpenIE edges with identical normalized endpoints, and the object is absent from the source passage for 0 of these 233 edges (0.0%; Wilson 95% upper bound 1.6%), against 2.8% of all non-gold edges (0.4% when the object string occurs elsewhere in the corpus). One gold triple enters only through edges whose endpoint takes the Wikidata spelling of a name the passage writes differently; all of its tokens are in the passage. On MetaQA the count is 0 of 976 edges (927 of 1,728 KB path triples matched; upper bound 0.4%; non-gold 3.0%). A loose token-containment match raises 2Wiki coverage to 576 triples; 9 of its 864 edges have an object not found verbatim, but in all 9 at least 80% of the object's tokens occur in the passage (merged or clause-length spans). On GraphRAG-Bench medical, 8 of 239 gold-matched edges (3.3%) have an absent object, against 2.6% for non-gold edges with corpus-attested objects; on inspection these are plural, punctuation and paraphrase variants ("biomarker" in a chunk that says "biomarkers"). We therefore find no gold fact that the extractor could only have supplied from memory. The check is limited: it sees only gold triples reproduced with matching surface forms (26.9% of 2Wiki triples under exact matching), it cannot exclude an injection rate below about 1.6% on 2Wiki, and it cannot detect memory acting within a passage, for instance an extractor that recovers passage-stated gold relations more reliably because it has read these pages. The OpenIE KG is grounded in its source passages, but this does not show it is free of pretraining influence.
