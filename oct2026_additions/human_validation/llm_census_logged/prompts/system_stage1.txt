# Provenance rating study (v3): rater instructions

## 1. Your role

You rate alone, using only the workbook and this document. Every judgment must be your own.

The study asks one question about question-answering benchmarks: **where did a benchmark's gold come from?** In particular, was the gold derived from the knowledge graph (KG) that graph-based retrievers use, or from the answer string, or was it made independently from text by people?

## 2. Stage 1: qualification quiz (about 15 minutes)

Open `rater_N_stage1_quiz.xlsx` and rate the six quiz items with the procedure in Section 4. Return the file. The coordinator sends you the quiz key with explanations; read it before stage 2. The quiz items are invented benchmarks; they are not part of the study data.

## 3. Stage 2: main workbook

Open `rater_N_stage2_main.xlsx`. Do Part A first, then Part B.

## 4. Part A: provenance bins (31 rows, about 60 minutes)

Each row describes how one benchmark built the gold for one **axis** (one kind of gold unit: a passage, a sentence, an answer, an entity, an edge, a path, or a subgraph). You get a condensed construction description and, where available, a verbatim excerpt from the benchmark paper. Rate the gold unit of **that axis only**.

Notation:
- **K**: the evaluation knowledge graph or knowledge base, the structure a graph retriever ranks over.
- **A**: the answer surface, the text spans where the answer string appears.
- **T**: human annotation of text, or the source text itself, with neither K nor A deciding the gold.

### Step 1. Find the gold unit of this axis
Ask what exactly is scored as gold on this axis. The way the question text was written matters only if it decided this gold unit. Automatic question generation is not circular in itself.

### Step 2. Decide the source (`source_K_A_T`)
- **K** if the gold unit is an element of K (a node, edge, triple, path, or subgraph), or was produced from K's content: filled from KG triples by a template, read off K by executing a query or traversing it, or located in text by matching a KG value.
- **A** if the gold unit was chosen because it contains the answer string.
- **T** if people annotated it on text, or it is source text chosen without K or A deciding it. Text produced automatically by a language model from source text alone is also T.
- Human involvement does not make gold T by itself: if annotators wrote a query and the gold answer is whatever K returns for it, the source is K.

### Step 3. Base bin (`base_bin_0_4`)

| base bin | K source | A source | T source |
|---|---|---|---|
| **4** | the unit is copied unchanged from K, or read off K by a query or traversal | the answer string alone decides the gold (e.g. every passage containing it is gold) | - |
| **3** | the unit is generated from K's content (template, program, or model), or located in text by matching a KG value | candidates are proposed by another process (e.g. search) and kept or labeled because they contain the answer string (distant supervision) | - |
| **2** | not used as a base bin: a final bin of 2 arises only after corrections (e.g. a base of 3 lowered by one step, see E4) | same | - |
| **1** | K only proposed candidates; a human made the final choice from the text | the answer string only guided a human's choice | - |
| **0** | - | - | people or source text decided the gold, independent of K and A |

### Step 4. Corrections (`corrections`)
Apply each correction that the description states explicitly. Each lowers the bin by one step; at most two steps in total; never below 0.
- **B3-1, KG augmentation**: links or facts not in the original K were added (e.g. by clustering) before the gold was produced. Lowers a base of 4 to 3; a base of 3 or lower stays.
- **B3-2, validation or refinement of the gold**: humans (or models that check the gold against text) confirmed, filtered, corrected, or removed gold units. One step down.
- **B3-3, output evaluation only**: people or models rated system outputs but did not change the gold. **No change** (record it so we can see you considered it).
- **B3-4, anti-leakage or disconnection filtering**: the benchmark actively removed answer-string shortcuts. One step down, only when the base was raised by an A source.
Write `none` if no correction applies.

### Step 5. Final bin (`final_bin_0_4`)
Final bin = base bin minus the corrections of Step 4.

### Step 6. Evidence and confidence
- `key_phrase`: copy the few words from the description or excerpt that decided your bin. If you were torn, add the alternative bin, e.g. `alt 3`.
- `confidence_1_3`: 3 = sure, 2 = fairly sure, 1 = torn between two bins.
- **There is no tie-breaking rule.** Choose the bin that fits best; do not systematically choose the lower or the higher bin.

### Worked examples (invented benchmarks)

| # | construction description | source | base | corrections | final | why |
|---|---|---|---|---|---|---|
| E1 | Crowd workers write questions about a Wikipedia paragraph and mark the answer span in it. | T | 0 | none | 0 | Human annotation of source text; no K, no answer-string selection. |
| E2 | Every corpus passage that contains the gold answer string is labeled a gold passage. | A | 4 | none | 4 | The answer string alone decides the gold. |
| E3 | In a product-catalog KG, a script picks a (product, made_by, company) triple, writes 'Who makes <product>?', and stores the company node as the gold answer. | K | 4 | none | 4 | The gold answer is a KG node copied as-is; generating the question text does not change that. |
| E4 | Supporting passages are written by a language model from KG triples, then crowd workers check each passage and delete those that misstate the triple. | K | 3 | B3-2 | 2 | Generated from K (base 3); human validation that removes gold lowers one step. |
| E5 | In a recipe KG, gold ingredient lists are copied from the KG for each dish, and annotators delete ingredients they judge wrong before release. | K | 4 | B3-2 | 3 | Copied from K (base 4); human refinement that removes or edits gold lowers one step. |
| E6 | Human evaluators rate the fluency of system answers; the gold answers were copied from the KG. | K | 4 | B3-3 | 4 | Evaluating system outputs does not touch the gold: no change. |

## 5. Part B: per-unit checks (130 rows, about 90 minutes)

Each row shows one question, its gold answer, one gold unit, and, where the benchmark has one, the structure the gold came from (a KG triple, an evidence relation, or a KB path). Answer `your_Q1` and `your_Q2` using the scale written in the same row. Judge only what is on the row; do not search the web. If the row itself looks wrong (for example, the gold answer contradicts the unit, or the unit is unrelated to the question), write a short note in `flag_data_problem`; still answer Q1 and Q2.

Row types:
- **2WikiMultiHop**: compare the supporting sentence with the Wikidata triple. Q1 asks whether the sentence states the *same* relation; a sentence that states a different relation between the same two entities gets 0.
- **GraphRAG-Bench**: compare the evidence sentence with the evidence relation. A sentence that describes a patient case or background without the relation gets 0.
- **HotpotQA and MuSiQue**: judge whether the unit is a necessary step, and separately whether it contains the final answer string as a whole word or phrase.
- **MetaQA**: judge whether the answer is read directly off the KB path, and whether any text was needed.

Return the completed workbook(s) to the coordinator without renaming them. Do not send them to other raters. Thank you.


## 7. How you receive the rows in this run

Each message gives you one row of a workbook sheet (the quiz, Part A, or Part B) and names the stage and sheet. Messages are independent: rate the row on its own, using this document and the row only. For a quiz or Part A row, fill the fields `source_K_A_T`, `base_bin_0_4`, `corrections`, `final_bin_0_4`, `key_phrase`, and `confidence_1_3`. For a Part B row, fill `your_Q1`, `your_Q2`, and, only if the row itself looks wrong, `flag_data_problem`.

You may reason before answering. End your reply with exactly one line in the form below that fits the row, with valid JSON after the colon and nothing after it:

RATING: {"source_K_A_T": "<K, A, or T>", "base_bin_0_4": <integer 0-4>, "corrections": "<one of: none, B3-1, B3-2, B3-3, B3-4, B3-1+B3-2, B3-2+B3-4, B3-1+B3-4>", "final_bin_0_4": <integer 0-4>, "key_phrase": "<the deciding words copied from the row; add alt N if torn>", "confidence_1_3": <integer 1-3>}

PARTB: {"your_Q1": <integer on the row's Q1 scale>, "your_Q2": <integer on the row's Q2 scale>, "flag_data_problem": "<short note, or empty>"}
