## C. Uncertain / borderline scores flagged for adjudication

1. **GRADE supporting-fact axis (bin3) vs supporting-passage axis (bin1) — axis definition collision.**
   The construction says "all supporting facts are contained in the edge set P" (KG edges -> K -> bin3 after B3-1), but the *retrieval* gold at eval time is text chunks ("supporting evidence traces back to original source documents" -> T -> bin1). Which axis counts as "the supporting-gold" the rubric's STEP1-default (supporting-passage) points to is genuinely ambiguous: the dataset's stated gold supporting facts are KG edges, yet the retrieval pipeline scores against text chunks. I scored BOTH axes (per STEP1 transparency) but the **default-axis assignment** (passage=bin1 vs supporting-fact=bin3) is where Rater B may diverge by 2 bins. **This is my most uncertain score.** The audit doc estimated C≈0.5-0.7 (bin2) as a single number; my axis-split gives bin1 AND bin3 with no bin2 — a structural disagreement with the audit's point estimate that adjudication must resolve. Note the ar5iv reading ("answer = terminal node ek+1", "supporting facts = edge set P") shows GRADE is **more KG-derived than the audit assumed**, pushing the answer/supporting-fact axes toward bin3, not bin2.

2. **2WikiMultiHopQA supporting-sentence axis: bin3 vs bin4.**
   The evidence triple is verbatim Wikidata (clearly bin4), but the sentence-level supporting facts are obtained by a heuristic that checks "whether the value o1 must appear in the Wikipedia article for entity e1" and records sentence indices. This is KG-value projection onto text (K-derived) but the *sentence surface* is Wikipedia text, not a KG copy — partial K. I scored bin3 (0.7~1) per the rubric's STEP5 pre-ruling ("evidence triple K=bin4, sentence alignment-heuristic -> partial K -> bin3"). A reasonable Rater B could read the heuristic as strong enough projection to call it bin4, or weak enough (surface is text) to call it bin2. ±1 bin instability either side; flagged as adjudication-eligible (|distance|=1, conservative-low rule would pick bin3 anyway).
